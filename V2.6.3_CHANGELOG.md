# V2.6.3 — Collection Node Inventory & Safe LoRA Controls

Fixes misconceptions from the earlier parameter-only list: V2.6.2 showed only *literal editable inputs in the compiled backend prompt*, not the full source UI graph. A skipped node did not necessarily mean it was missing or running.

## What's new

- Advanced settings now show **合集节点与运行状态** above the editable parameter list, for collection workflows only.
- The initially collapsed panel displays per-function counts and supports filtering by node ID, name, type or state. Opening it shows source-graph nodes belonging to the selected function, including upstream dependencies and relevant frontend tools.
- Status is determined from **compiled API prompt node IDs**, not visual position alone. Distinguishes: running, originally bypassed, disabled, outside current output path, frontend controls, frontend comparison.
- Qwen 2.1 high-resolution editing: displays `679` KSampler (already in old parameter list), `672` rgthree Image Comparer, `669` high-resolution Fast Groups Bypasser, `689` image-2 group controller, and bypassed optional LoRA `690/696/692`.
- Allows explicit per-subfunction opt-in for *originally bypassed* `LoraLoaderModelOnly` / `LoraLoader` nodes that are upstream of the selected output. Other nodes cannot be turned on using this generic LoRA switch.
- Recompiles the execution graph and checks dependencies before committing a LoRA switch. Invalid or unavailable nodes result in an error with no prompt/state mutation. Submissions are disabled while recompilation is in progress.
- Enabled LoRAs then appear in the regular editable parameter list (with `/object_info` metadata if available). Original bypass status remains unchanged when they are off.
- Stores enabled optional LoRAs separately for each subfunction. Existing V2.6.2 profiles start with no new LoRA enabled, preserving previous results and input/mask records.
- Optional image 687 still has its own enable switch in the input-image section. Toggling the image preserves previously enabled LoRA choices, and vice versa.
- Updated `versionCode=20`, `versionName=2.6.3`; preserved the PKCS12 release signing pipeline and GitHub Secrets configuration. No private signing files are included.

## Important distinctions and limits

- `672 Image Comparer` is a **ComfyUI browser-side image comparison widget**, not a second independently executable backend output. This version shows its identity/role; it **does not** implement a new draggable A/B comparison viewer on Android.
- `669` and `689 Fast Groups Bypasser (rgthree)` are **frontend group controllers**, not backend `/prompt` nodes. Use the existing subworkflow selector and optional reference-image toggle instead of pretending that the rgthree UI itself executes on the phone.
- The inventory shows relevant original nodes; only the backend prompt defines what really runs. Re-activating a LoRA can change model behavior substantially and requires the model files to exist in ComfyUI.
- The current example and synthetic logic checks were performed offline. Final `assembleRelease` and live multi-function rendering must be verified on your Android device and ComfyUI server.

## Manual acceptance test

1. Upgrade V2.6.2 in place, verify workflow library/folders, masks and saved images remain.
2. Choose high-resolution editing in Qwen Image 2.1; expand **高级设置 → 合集节点与运行状态 → 展开全部节点结构**.
3. Search `679`, `672`, `669`, `689`, `690`, `696`, `692` separately. `679` should be executable, `672` frontend comparison, `669`/`689` frontend controls, and `690/696/692` bypassed by default.
4. Toggle only LoRA 690, verify it enters the executable node count and advanced editable fields, while 696/692 remain bypassed. Toggle it off and confirm the original state.
5. Try optional image 687 together with a LoRA toggle; check that both choices survive independently and correctly populate the Qwen `705` inputs.
6. Switch to another collection function and back: state persists only in the original variant. Check the generated output and missing-node warnings on the actual ComfyUI server.
7. Verify old ordinary single-function workflow parameter editor, gallery, search and mask painting are unaffected.
